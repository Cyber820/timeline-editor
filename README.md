# Timeline Editor

电子游戏史时间轴、二维矩阵及相关数据编辑工具。

## 1. 项目结构

### public/

静态页面和前端资源。

包含：
- 世界电子游戏史时间轴（中文、英文）
- 中国电子游戏史时间轴（中文、英文）
- 世界电子游戏史二维矩阵（中文）
- 数据编辑页面
- 其他测试及辅助页面

目录详细说明：
`public/README.md`

### public/src/

前端JavaScript模块。

包含：
- 时间轴绘制
- 二维矩阵绘制
- 数据读取
- 数据源配置
- 过滤
- 自定义格式
- UI组件
- 通用工具

目录详细说明：
`public/src/README.md`

各模块的具体函数和参数，
由对应模块目录内的README负责记录。

### server/

服务端API及样式规则编译功能。

主要子目录：
- api/
- compiler/

### public/archive/

旧版页面及归档资源。

## 5. 数据来源原则

当前时间轴通过Google Apps Script接口
读取Google Sheets事件数据。

地区和语言对应的数据源配置位于：

`public/src/variant/variant.js`

标准化数据读取模块位于：

`public/src/timeline/fetch.js`

二维矩阵复用以上模块。

第一阶段不修改Google Sheets、
Apps Script接口及现有数据源配置。

## 6. 代码开发与文档规范

### 6.1 模块化

按功能划分代码目录。

不同展示模块可以复用公共业务逻辑，
但应避免直接依赖其他视图的内部绘制代码。

### 6.2 根目录README

负责描述：
- 项目结构
- 各目录职责
- 根目录代码及说明文档用途
- 主要入口和依赖关系

### 6.3 子目录README

负责描述：
- 每个代码文件的功能
- 主要函数及接口
- 参数及其类型
- 返回值
- 依赖模块
- 重要约定
- 扩展和修改注意事项

### 6.4 新增代码

新增代码目录时：
1. 在上一级README登记。
2. 创建该目录的README。
3. 记录该目录中每个文件的职责。
4. 记录主要函数及参数。

### 6.5 修改代码

修改现有代码时：
1. 确认可能受影响的调用方。
2. 检查是否改变公开接口。
3. 更新所在目录README。
4. 如目录职责发生变化，更新上级README。
5. 测试通过后再提交和部署。

### 6.6 稳定性原则

- 不为新增视图随意修改旧视图。
- 尽量复用既有的数据与业务模块。
- 不擅自改变现有Google Sheets数据结构。
- 不擅自改变已有过滤与格式功能的行为。
- 不删除仍被引用的历史兼容模块。
- 每完成一个独立阶段，进行功能验证。
